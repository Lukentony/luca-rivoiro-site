Il problemaThe problem

Se un agente propone «rm -rf /tmp» per analizzare lo spazio disco, non mi affido alla sola istruzione data al modello. Nella demo una regola esterna ferma «rm», che non è nella allowlist, prima che il comando arrivi alla shell.If an agent proposes "rm -rf /tmp" to analyze disk usage, I don't rely only on its instructions. In the demo, a rule outside the agent stops "rm", which isn't on the allowlist, before the command reaches the shell.

Cosa ho costruitoWhat I built

Ho scritto un middleware Python tra l'agente e la shell. Nel caso qui sopra basta il primo controllo, la allowlist. Dopo cerco offuscamenti con regex e confronto il comando con il task. Se il caso è ambiguo, interviene anche una verifica LLM. I test automatici girano in CI. Il servizio usa utenti non privilegiati e parte in dry-run; i comandi fuori dalla pipeline non sono coperti.I wrote Python middleware between the agent and the shell. The first check, the allowlist, stops the example above. Next I use regex to check for obfuscation and compare the command with the task. An LLM check handles ambiguous cases. Automated tests run in CI. The service uses unprivileged users and starts in dry-run; commands outside the pipeline aren't covered.

Ruolo: Software Developer (open source), dal 2026. Il codice è pubblico. Non c'è una sandbox forte: in produzione non lo metterei.Role: Software Developer (open source), since 2026. The code is public. There's no strong sandbox: I wouldn't put it in production.
